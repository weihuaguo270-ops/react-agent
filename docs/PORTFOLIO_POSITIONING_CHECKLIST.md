# 三仓对外口径检查清单

## 1 分钟检查

- [ ] 外人能说出使用者：企业内部员工。
- [ ] 外人能说出两件事：规范咨询、报销办理。
- [ ] 仓库名与英文工作名统一为 work-assistant，中文名为企业内部智能工作助手；Python 包、命令和环境变量保留兼容名称。
- [ ] 没有把“三大业务线”或“通用 Agent 框架”放在首页主标题。
- [ ] change-delivery 仅以「已独立且已停止、不再作为本仓业务线」一句出现（若提及）；不写成规划中产品或跨仓默认入口，也不再保留本仓附录/demo/Skill 入口。
- [ ] trace-debugger 被描述为轨迹失败雷达与 CI 钩子。
- [ ] llm-eval-engine 被描述为发版前自检，输出 pass/review/hold。
- [ ] 闭环顺序是：产出轨迹 → trace-debugger → llm-eval-engine。

## 证据边界

- [ ] 所有公共入口保留“可部署、可评测的工程原型”。
- [ ] 明确证据包含合成任务与 external_real_sandbox。
- [ ] 没有把离线 κ、黄金集数量、模型榜或沙箱结果写成生产 SLA。
- [ ] 没有宣称生产 SaaS、多租户、长期线上流量或企业权限体系。
- [ ] 「3 个项目、30 条真实任务、10 条独立 held-out」写明为已放弃的发布门槛；当前路线不再把它或「补齐跨仓账本 golden / held-out」写成 P0 或下一阶段必做事。
- [ ] 现有离线评测、golden/故障/生产盲测和轨迹闭环仍是原型证据；放弃门槛后没有写成生产成熟度或生产可发布。
- [ ] 没有为 trace-debugger 或 llm-eval-engine 规划补齐该门槛，也没有把它们写成简历第三项；工作助手简历简介未被改写去承诺该门槛。

## 文件边界

- [ ] 本仓不再保留 change-delivery 运行入口；独立仓若仍存在，不构成本仓默认闭环。
- [ ] 不重写 Agent 循环，不删除评测脚本或评测集。
- [ ] 历史报告和归档材料只作为证据引用，不作为首页产品名。
