# Expense 政策边界与规则契约

## 1. 文档状态

本文是 Expense 阶段 0 的政策边界记录。它把当前仓库中的示例政策转换为可测试的规则契约，并明确尚不能从现有政策或 Claim 字段推出的行为。

本文不代表现实企业财务政策或税务合规结论。`fixtures/expense/expense_policy.md` 仍是政策语料；本文件和 `expense_policy_v2.json` 共同定义项目模拟企业的可执行规则。项目不预设适用国家或地区，当前发布的 `project_simulation_v1` 使用 USD 作为模拟基准币种。

## 2. 当前业务范围

当前 Expense 承诺离线、结构化 Claim 的模拟政策决策。金额、城市/目的地目录、审批矩阵、汇率和日历由已发布的 `project_simulation_v1` 提供；真实付款、财务入账和外部系统连接仍不在范围内。

以下能力不属于阶段 0 已确认范围：真实付款、财务入账、税务合规、跨币种自动换算、组织级审批矩阵、节假日日历和外部采购系统校验。

## 3. 决策优先级

规则按以下顺序执行：

1. 输入合法性和字段完整性；
2. 硬性拒绝规则；
3. 类目额度与事前审批；
4. 审批级别；
5. 需要人工确认的例外。

任何字段缺失、政策冲突、未知类目或无法证明的前提都必须失败关闭，进入 `invalid_claim` 或 `needs_review`，不得默认批准。

## 4. 已冻结的 v1 规则

| 规则 | 条件 | 决策/状态 | 证据边界 |
|------|------|-----------|----------|
| 凭证要求 | 正式 Claim 的凭证状态无效，或 `has_receipt=false` | `reject_no_receipt` | 只有凭证字段；不验证发票真伪 |
| 类目额度 | `amount > category_limit` 且没有有效事前审批 | `reject_over_limit` | 额度来自带版本的 policy facts |
| 审批阈值 | `amount <= 200` 且没有更高优先级规则 | `approve_manager` | 表示所需审批级别，不等于已完成审批 |
| 审批阈值 | `200 < amount <= 1000` 且没有更高优先级规则 | `approve_finance` | 表示需要财务复核 |
| 审批阈值 | `amount > 1000` 且凭证有效、没有更高优先级规则 | `approve_director` | 表示需要总监审批 |
| 预审批 | 有有效事前审批时，跳过“无预审批超额拒绝”，仍执行凭证、类目和审批级别规则 | 继续评估 | 旧 Claim 的布尔字段只用于 legacy adapter |

`approve_*` 是决策码，不是正式 Claim 的终态。正式流程必须经过审批记录和权限闸门；`escalated` 始终是非终态。

## 6. Claim 最小字段契约

正式表单 Claim 在进入决策前至少需要：

```text
claim_id
claim_version
category
amount
currency
occurred_on
description
has_receipt
receipt_refs（有凭证时至少一个）
pre_approved 或 pre_approval_ref
```

Claim 使用“公共信封 + 类别专用载荷”。`category` 是类别判别标识，建议使用稳定枚举 `meal`、`transport`、`lodging`、`office_purchase`；类别载荷至少包括：

| 类别 | 专用字段（候选） |
|------|------------------|
| `meal` | `expense_type`、`business_purpose`、`participants` |
| `transport` | `transport_mode`、`route_scope`、`origin`、`destination`、`seat_class`、`booking_channel` |
| `lodging` | `city_code`、`city_tier`、`check_in`、`check_out`、`nights`、`room_type`、`booking_channel` |
| `office_purchase` | `purchase_order_id`、`vendor_id`、`item_type` |

上述枚举、城市目录和节假日口径是项目模拟规则，不表示现实组织的正式政策。字段缺失、枚举未知、城市目录版本不可用时必须失败关闭。

金额必须是有限非负数；日期必须是 ISO 日期；金额、币种、日期和凭证引用不能依赖自然语言猜测。旧 `/v1/chat` 和 `expense_claim_review` 可继续接受 legacy Claim，但只能通过兼容 adapter 进入规则；它们不能被当作正式表单提交已完成。

## 10. 公开政策依据与项目模拟规则

公开政策用于提炼控制模式，不直接移植其币种额度、授权层级或法律范围。当前候选规则如下：

| 领域 | 公开政策依据 | 本项目候选规则 | 状态/限制 |
|------|--------------|----------------|-----------|
| 业务目的与凭证 | 华为云慧通公开问答要求因公标准费用，合理费用按公司规定凭票报销；大连泰维公开制度以出差计划、路线和有效单据为管理基础 | Claim 必须提供业务目的、描述和收据引用；缺失拒绝进入自动决策 | 字段校验已实现；不验证票据真伪 |
| 交通 | 公开企业政策普遍采用事前申请、平台预订、按交通等级控制；华为云慧通和 GitLab 提供流程参考 | 模拟 profile 使用市内标准出租/公共交通、城际二等座铁路、城际经济舱；航班必须提供市场参考价，超过 20% 转人工 | 组合和动态价校验已实现 |
| 住宿 | 公开企业政策按目的地/市场额度设上限；GitLab 原文给出标准房间 300 USD/晚含税和动态价格复核 | 模拟 profile 按市场目录计算每晚额度；必须提供每晚市场参考价，超过 20% 转人工 | 目录缺失、市场价缺失或超阈值转人工 |
| 餐饮与娱乐 | GitLab 和国内公开资料均强调业务目的、凭证和例外审批；具体人均额度依组织配置 | 模拟 profile 使用 200 USD 单笔阈值；娱乐类使用独立人工审核路径；周末日期本身不拒绝 | 具体额度属于项目模拟假设 |
| 办公采购 | 公开企业政策支持费用与采购流程闭环，但格式和系统因组织而异 | 缺少 `purchase_order_id` 返回 `reject_missing_purchase_order`；有单号但无法连接采购系统核验时转人工 | 已实现字段缺失拒绝和无法核验转人工；采购系统未接入 |
| 多币种 | 公开政策通常要求本地币种提交或使用组织汇率 | 当前非 USD 一律 `needs_review` | 已实现；模拟版不自动换算 |
| 例外处理 | 国内企业制度普遍要求超标准事项事前申请或更高权限审批；公开上市公司文件支持“超标需授权/个人承担”的控制模式 | 超出已列组合、无法取得政策事实或属于未覆盖例外，一律转人工并保留原因 | 结构化审核结果已覆盖部分场景；正式审批状态和持久化审计尚未接入 |

项目使用 USD 作为模拟基准币种。餐饮 200、交通 500、办公采购 1000、目的地市场分层和 PO 格式是项目模拟假设；GitLab 的 300 USD/晚、动态价格 20%、收据和月度复核条款是制定依据。它们已经固化到 `expense_policy_v2.json` 的 `project_simulation_v1`，不代表现实企业通用标准。

## 11. 外部参考（仅作方案依据）

以下公开资料用于形成项目模拟规则；政策中标注的具体金额和枚举由本项目自行设定：

- [华为云慧通差旅：费用报销员工常见问题](https://support.huaweicloud.com/prepare-hctms/hctms-0013.html)：国内企业差旅平台公开说明，涉及标准差旅费用、凭票、月结和酒店发票。
- [大连泰维精密模具股份有限公司《差旅费管理制度》](https://pdf.dfcfw.com/pdf/H2_AN201711271058507837_1.pdf)：上市公司公开制度文件样本，作为国内企业流程控制参考，不作为本项目金额标准。
- [GitLab Global Travel and Expense Policy](https://handbook.gitlab.com/handbook/finance/expenses/)：公开企业政策，包含收据、动态酒店额度、航班舱位、异常审批、当地币种和财务汇率处理。
- [Navan: Developing effective corporate travel policies](https://navan.com/blog/corporate-travel-policies)：差旅平台的政策设计建议，强调目的地/市场动态额度、预审批和实时合规。
- [Australian Government Travel Policy](https://www.finance.gov.au/publications/policy/australian-government-travel-policy)：公共机构基准，强调业务必要性和成本合理性。

项目采用地区无关的 policy profile 边界：公开来源用于提炼流程、凭证、价格和例外控制，项目模拟规则负责给出可执行金额、币种、城市目录、席别枚举、节假日和汇率行为。该 profile 是项目内部模拟设定，不是任何现实企业政策的复制。
