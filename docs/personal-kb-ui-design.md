# 个人知识库界面设计规范

## 一、设计目标

将企业内部「个人知识库」做成可长期工作的文档工作区：
- **左栏文档库**：可扫读的文档列表；仅从此处加入本地文件
- **中间正文**：打开某篇后阅读/编辑；未选中时留空，不隐藏这一栏
- **右侧对话**：链接、粘贴、要求、联网检索与生成都在这里完成

基本单位是文档和摘要，不是标题/关键词卡片，也不是「投递 / 收藏 / 提问」柜台。视觉为纸色/墨色、细线、短办公用语，不采用蓝灰 AI 模板，也不仿造 Obsidian、OpenCode 等品牌界面。

对齐的是参考图里的三分区工作区，不是整套仓库或插件系统。本刀不做文件夹产品；若后续有分组再显示为目录。

---

## 二、整体架构

### 2.1 页面层级

```
┌─ 身份入口页（未确认时）
└─ 工作区（确认后）
   ├─ 顶栏（身份 + 刷新 / 更换身份）
   ├─ 提示横幅（未接入模型等）
   └─ 三栏主工作区
      ├─ 左栏：文档库（列表 + 本地文件加入）
      ├─ 中栏：正文（始终占位；未选中时为空）
      └─ 右栏：对话
```

### 2.2 布局原则

- **宽屏**：三栏同时显示；中栏未选中文档时仍保留空栏
- **窄屏**：在「文档 / 正文 / 对话」三栏之间切换，不退回单页堆叠，不做柜台入口

### 2.3 视觉风格

- 背景：纸色 `#faf9f7`、白 `#ffffff`
- 边框：细线 `#d4d1cc`；正文墨色 `#1a1816`、辅助 `#736b5e`、链接 `#3d5a80`
- 1px 细线，不用大圆角和投影；短办公用语

---

## 三、文档创建（仅两条路）

1. **左栏**：手动加入本地文件（PDF、Markdown、文本等已支持格式）。左栏**不要**出现链接、粘贴正文、摘要要求表单。
2. **右栏对话**：用户发送链接、粘贴内容或提出要求；Agent 检索、整理或生成；用户确认后保存进当前身份个人库，出现在左栏，可在中间打开。同一链接再次处理合并更新，不重复建条。

链接、要求、联网检索和生成一律在右侧对话中完成，不放到左栏或中间栏表单。

打开某篇文档时，右侧对话应针对当前这篇处理（改写、摘要、补充），请求携带 `document_id`。

空库说明：还没有文档。可在左侧加入本地文件，或在右侧对话中生成。

---

## 四、模型接入

工作区对话默认走 Agent 底座同一套 `llm_config.json` / `LLM_PROVIDER` 与 `react_loop`。配置可用则正常启动后即可对话，**不**再要求额外打开 `REACT_AGENT_SERVER_LLM=1`。

页面根据 `/v1/info` 的 `llm_available` 判断；不要用「默认应用不是 default 就当成未接入模型」。界面**不**展示实现名称或环境变量。

无可用模型时：明确说明还不能对话和生成；仍可在左侧加入本地文档；不得用离线规则脚本冒充灵活对话。

CI / 必须离线的测试显式设 `REACT_AGENT_SERVER_LLM=0`（或等价强制离线），不在无密钥检查里改去调用真实模型。报销线保持离线。

---

## 五、关键界面

### 5.1 身份入口

标题「个人知识库」，确认后进入工作区。身份隔离不变。

### 5.2 左栏

- 可扫读列表：标题 + 来源/日期
- `+`：仅选择本地文件加入
- 空状态：还没有文档。可在左侧加入本地文件，或在右侧对话中生成。

### 5.3 中栏

- 始终存在
- 未选中：从左侧选择一篇文档阅读。
- 选中：标题、来源、摘要、正文；可编辑保存
- 关闭后回到空栏，不隐藏中栏

### 5.4 右栏

- 标题「对话」；初始可为空
- 占位：发送链接、粘贴内容，或提出整理要求
- 选中文档时显示「正在阅读：{标题}」
- 未接入模型：禁用输入，说明仍可在左侧加入本地文件（不写环境变量名）

### 5.5 横幅（未接入模型）

当前未接入对话模型，暂不能通过对话改写或生成文档。仍可在左侧加入本地文件。

---

## 六、边界（不变）

- 身份隔离
- 非法 URL 拒绝
- 提问只在个人库检索
- 依据不足回复「个人库中没有足够依据」，不回退内置语料
- 生成文稿保存进个人库工作区，不做「保存到指定本地路径」

---

## 七、API 时机

| 动作 | 接口 |
|------|------|
| 列表 | `GET /v1/docs/personal/documents` |
| 打开正文 | `GET /v1/docs/personal/documents/{id}` |
| 本地文件加入 | `POST /v1/docs/personal/ingest`（filename + content_base64） |
| 对话 | `POST /v1/docs/personal/chat`（message，可选 document_id） |
| 模型是否可用 | `GET /v1/info` → `llm_available` |
