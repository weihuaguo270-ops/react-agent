# 项目当前状态总结

## 项目定位

work-assistant 是企业内部智能工作助手的工程原型，面向同一员工身份下的规范咨询和报销办理。仓库名与英文工作名统一，既有 Python 包和命令保留兼容名称。

可以表述为可部署、可评测的 Agent 应用原型；不能表述为生产 SaaS、长期线上 SLA、企业多租户权限平台或自动根因诊断系统。

## 当前闭环

| 部分 | 状态 |
|---|---|
| 规范咨询 | 已有文档检索、引用校验、拒答策略、现场证据和离线评测入口 |
| 报销办理 | S0–S8 原型验收已 complete：政策决策、表单/运营台、SQL 持久化 Claim/审批/工单、扩展 candidate held_out/golden、PostgreSQL 物理重启均有本阶段证据；仍不代表生产财务系统或 SLA |
| 轨迹与质量 | Format B、Harness、trace-debugger 失败扫描和 llm-eval-engine 发布前自检已形成跨仓闭环 |
| 生产成熟度 | 原型验收不等于生产可发布；真实业务接入、付款入账与生产 SLA 仍有缺口，不能宣称生产成熟度 |
| 已放弃的发布门槛 | 「3 个项目、30 条真实任务、10 条独立 held-out」不再作为当前或下一阶段目标；跨仓账本 golden 仍为 0 的历史事实保留；现有离线验收仍是原型证据 |

`change-delivery`（受控变更交付）已独立且已停止，不再作为本仓业务线；本仓已移除其文档附录与运行入口。

## 证据边界

- 当前证据包括合成任务、离线评测和 external_real_sandbox。
- 沙箱中的真实 GitHub 写入、Draft PR、接受/拒绝和回滚演练不等于生产用户流量。
- κ、黄金集数量、模型选型榜和失败门属于验收附录，不是产品主标题。

## 跨仓职责

~~~
工作助手产出轨迹
  → trace-debugger：失败打标、scan/compare、CI
  → llm-eval-engine：过程/业务证据与 pass/review/hold
~~~

## 已放弃的发布门槛

2026-11-16 放弃「3 个项目、30 条真实任务、10 条独立 held-out」。不再补齐跨仓账本 golden，不再补齐 held-out，也不再把这条门槛当作下一阶段必做事。该门槛会卷到独立质量仓 llm-eval-engine 与 trace-debugger；本仓不为这两个评测仓规划补齐，也不把它们写成简历上的第三项。简历简介仍只写工作助手，库存预占留在另仓。

现有离线评测、golden/故障/生产盲测入口、轨迹与质量配件闭环保留为原型评估证据。S0–S8 报销原型验收已收口。上述证据不构成生产成熟度。
