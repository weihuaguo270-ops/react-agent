# 企业 Agent 业务范围与指标边界

本项目面向企业任务执行与 Agent 评测，不以“能对话、能调用工具”作为完成标准。当前企业主业务线为
软件工程交付和技术支持/工单辅助；安全研判、报销审核等作为跨域 benchmark；RAG、轨迹、Episode、权限、Sandbox、过程评测和推理性能
属于共享能力层。

## 业务结构

```text
企业 Agent 应用
├── 软件工程交付
│   └── Issue → 隔离修改 → 验收测试 → 审批 → 候选提交 / Draft PR
├── 技术支持与工单辅助
│   └── 现场证据 → 检索 → 根因候选 → 验证建议 → 修复建议 / 升级
├── 跨域 benchmark
│   ├── 安全研判：CVE/IOC → 证据关联 → 引用报告 → 人工复核
│   └── 报销审核：规则 → 状态决策 → 审计事件
└── 共享能力
    ├── RAG / 多跳检索
    ├── ToolGuard / 权限 / Sandbox
    ├── Format B 轨迹 / EvaluationEpisode 与失败治理
    └── 过程评分、版本门禁与推理性能
```

通用执行集和公开 QA 仍用于能力回归，但不作为独立企业业务线；跨域 benchmark 用于验证同一套评测契约能否覆盖不同任务和风险等级。

## 软件工程交付

实现入口：`apps/github_delivery.py`。运行报告同时保留技术证据和业务指标：

| 指标 | 当前定义 | 当前证据边界 |
|------|----------|--------------|
| task_success_rate | 变更生成且验收测试通过 | 本地隔离克隆/合成 Issue |
| acceptance_test_passed | 测试子进程返回成功 | 仅任务声明的测试，不含隐藏测试 |
| human_handoff_rate | 因缺少审批进入人工队列 | 流程信号，不等于真实 Review 工时 |
| unauthorized_external_write | 未经外部写审批产生 PR | 本地测试默认不访问写接口 |
| duration P95 | 单次交付工作流墙钟时间 | 本机环境，不能外推生产 SLO |
| rollback_ready | 已生成可撤销候选提交 | 不代表线上部署回滚完成 |

工程交付以验收测试和最终仓库状态为主验证器，Judge 只作为过程质量补充，不能覆盖
可执行验证器的结论。

## 技术支持与工单辅助

实现入口：`apps/docs_troubleshoot`。故障集与生产盲测报告新增业务 scorecard：

| 指标 | 当前定义 | 当前证据边界 |
|------|----------|--------------|
| task_success_rate | 用例的答案、引用和策略断言全部通过 | 离线用例，不是线上工单关闭率 |
| grounded_resolution_rate | 通过且包含正确文档证据 | 文档充分性，不等于问题已在现场修复 |
| root_cause_hit_rate | 根因关键词命中冻结期望 | 候选命中，不是因果验证 |
| wrong_suggestion_rate | 命中禁止建议的比例 | 禁止词规则，不能覆盖所有危险建议 |
| evidence_sufficiency | 现场证据与文档规则的充分度 | 仅适用于提供了现场证据的样本 |

当前输出的 escalation 是建议文本，不代表已创建工单、呼叫 on-call 或完成真实人工
交接，因此暂不报告“人工接管率”“首次解决率”和“平均工单处理时长”。这些指标必须
接入工单状态和人工操作记录后才能启用。

## 共享业务指标接口

`react_agent.eval.business_metrics` 提供：

- `business_scorecard`：任务成功、失败、人工介入和时延摘要；
- `compare_scorecards`：比较 Agent 版本，硬指标退化时输出 `hold`；
- 空切片和不适用指标分别使用 `0.0` 与 `None`，避免把“没有证据”当作零分。

发布门禁必须按业务切片比较，不允许用通用 capability 总分覆盖 held-out 或关键风险
切片的退化。

## 明确不宣称

当前实现不能证明：

- 真实企业生产流量下的软件交付成功率或工单首次解决率；
- Agent 节省了多少人工工时或带来多少财务收益；
- 对任意仓库、任意故障类型或任意企业权限体系均有效；
- 自动根因定位、自动执行生产修复或无人审批发布；
- 多租户 SLA、线上灰度、自动回滚和完整安全认证；
- 公开子集结果等价于 SWE-bench、τ-bench 或其他完整行业榜单成绩。

只有在接入真实任务责任人、冻结业务验收标准、记录人工基线和线上最终状态后，才可
将本地指标升级为生产业务指标。

## 下一阶段

1. 软件交付接入真实历史 Issue、隐藏测试和 Review 结果，统计一次通过率和返工时长。
2. 技术支持接入脱敏工单、日志/Trace 只读连接器和真实关闭状态，统计首次解决与重开。
3. 为两个企业业务线及跨域 benchmark 分别冻结 baseline、golden、held-out 和关键风险切片。
4. 将任务成功、错误副作用、人工介入、P95 时延和单成功任务成本设为发布硬门禁。
