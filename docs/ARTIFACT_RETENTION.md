# 运行产物留存规则

运行时数据、冻结证据和源码使用不同目录，避免把一次本地执行误当成项目能力或评测基线。

| 类型 | 位置 | Git 策略 | 留存方式 |
|---|---|---|---|
| 本地运行轨迹 | `REACT_AGENT_TRAJECTORY_DIR` 或用户数据目录 | 忽略 | 调试结束后按需清理 |
| Memory / RAG 索引 | 用户数据目录 | 忽略 | 由使用者自行备份，不作为评测证据 |
| StepWatcher 日志 | 用户数据目录下 `.tdebug/` | 忽略 | 失败复盘完成后清理 |
| 临时评测和构建产物 | `.evidence_tmp/`、`dist/`、缓存目录 | 忽略 | 可随时重新生成 |
| 冻结评测快照 | `docs/snapshots/` | 跟踪 | 记录来源、日期和证据边界 |
| 测试数据与契约 | `fixtures/`、`schemas/` | 跟踪 | 随代码评审和版本发布 |

仓库根目录和 `src/react_agent/` 下不再保存运行时 `trajectories/`。需要复现失败时，
应使用冻结快照、测试 fixture 或外部证据目录，而不是依赖开发机历史日志。

清理时不得删除 `.env`、虚拟环境、人工评分数据、冻结快照或已发布的业务证据。
